\section{Initial Capability Baseline}
\label{Section:InitialCapabilityBaseline}
The baseline identifies a signal acquisition pipeline for Embedded Engineers,
with the following owner-supplied connection chain:

\begin{center}
Sensor $\rightarrow$ ADC0804 $\rightarrow$ FTDI245R interface
$\rightarrow$ host computer
\end{center}

This is an initial context statement, not a detailed allocation or implemented
architecture. Supported host operating systems in the initial baseline are
Linux, macOS, and Windows. Implementation and demonstrated compatibility are
not established. The reproducible-code-base objective is defined in
\hyperref[Section:ProjectPurpose]{Purpose}; measurable reproducibility criteria
remain \OwnedTBD{}.

\section{System Boundary and Allocation}
\label{Section:ProjectSystemBoundary}
The system of interest is the FTDI245R data acquisition pipeline code base.
Its hardware--software boundary separates pipeline-owned acquisition software
from the external hardware, platform services, and downstream processing
consumer on which it depends. The ADC0804, the 74xx counter, the peer
FTDI245R, the USB stack, the host operating system across Linux, Windows,
and macOS, and the downstream processing consumer are controlled external
dependencies at this boundary, as directed by the document owner.

These dependencies participate in the acquisition context but their internal
implementations are outside the pipeline code-base boundary. The dependency
register below identifies the contracts that the pipeline must account for
during later requirements and architecture work. The Sensor remains the
upstream external signal source. Its specific identity and connection
characteristics remain \OwnedTBD{}.

Detailed allocation among pipeline software components, firmware,
programmable logic, storage, and display remains \OwnedTBD{}. No counter topology,
device programming model, driver/API, or electrical behavior is inferred.
The term peer FTDI245R identifies the external endpoint specified by the
owner; its physical identity and relationship to the previously named
FTDI245R interface remain \OwnedTBD{}. No additional FTDI245R device is assumed.
